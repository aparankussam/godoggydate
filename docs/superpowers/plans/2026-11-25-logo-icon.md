# GoDoggyDate Logo and App Icon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the owner's final logo and app icon, unedited, as the web and mobile brand assets.

**Architecture:** Export the two supplied webp files to each platform's required sizes with macOS `sips` (resizing and format conversion only). Point the configs at the new files, and swap the text-and-paw header marks on the website for the logo image. A small node test pins file presence, pixel sizes and config references.

**Tech Stack:** macOS `sips`, Next.js (web, `next/image`), Expo (`mobile/app.config.js`), `node --test`.

**Spec:** `docs/superpowers/specs/2026-11-25-logo-icon-design.md`

## Global Constraints

- Source art: `docs/superpowers/specs/assets/2026-11-25-godoggydate-logo-final.webp` (1774×887) and `docs/superpowers/specs/assets/2026-11-25-godoggydate-app-icon-final.webp` (1254×1254).
- Artwork is used as supplied: resize and format conversion only. No recolouring, redrawing, or cropping of the file. CSS may frame the image (`object-fit`), but the file itself is never cropped.
- Brand colours: blue `#8FC9F2`, pink `#FF5C8D`, purple `#2A1F4A`, yellow `#F5B731`.
- Builder's call: the icon art has a white margin around its blue tile, so Android adaptive-icon and splash backgrounds use `#FFFFFF`. Any padding then matches the art's own edge.
- Before pushing, run `npm run build` in `web/` (user's global rule), as well as lint and tests.

## Review Focus

- A path in `manifest.json`, `layout.tsx` or `app.config.js` that points at a file that doesn't exist gives a broken icon with no build error. Task 1's test checks every referenced path exists.
- A PNG exported at the wrong size makes iOS and Android reject or blur the icon. Task 1's test reads the PNG header dimensions.
- The header logo on a phone (375px wide) must not push the "Sign in" button off-screen. Task 2 has a visual check at mobile width.
- The logo `alt` text must keep the accessible name "GoDoggyDate", because the link currently has aria-label "GoDoggyDate home". Task 2 keeps the aria-label.
- The old `icon.svg` (the paw) must not linger in the manifest or layout and win as the favicon. Task 1's test asserts no `icon.svg` reference.

### Task 2: Logo in the website headers

**Files:**
- Create: `web/components/BrandLogo.tsx`
- Create (binary): `web/public/brand/godoggydate-logo-animated.mp4`, converted from `docs/superpowers/specs/assets/2026-11-25-godoggydate-logo-animated.gif` with `ffmpeg -i <gif> -movflags +faststart -pix_fmt yuv420p -vf "scale=trunc(iw/2)*2:trunc(ih/2)*2" <mp4>` (format conversion only; the even-size scale is a 1px pad-free rounding that H.264 requires).
- Modify: `web/app/page.tsx:102-105` (landing header: replace `<PawCoin size={34} />` and the "GoDoggyDate" span), `web/components/AppNav.tsx:134-140` (app nav: replace the paw badge and the span), and the landing hero (place `<AnimatedLogo />` above the hero `<h1>`, at most 360px wide).
- Create: `web/components/AnimatedLogo.tsx` (client component): a `<video muted playsInline preload="auto">` of the mp4, no `loop`, `poster` set to the static logo, `role="img"` and `aria-label="GoDoggyDate"`. Behaviour:
  - **Play, hold, replay:** on `ended`, the video rests on its last frame (the full logo); after `HOLD_MS = 5000` it sets `currentTime = 0` and plays again.
  - **Only on screen:** an `IntersectionObserver` plays the video when it's visible and pauses it and clears the hold timer when it's not.
  - **Boop:** `onPointerEnter` (mouse only, so it doesn't fire on touch) and `onClick` restart it right away with `currentTime = 0; play()` and reset the hold timer. The element gets `cursor-pointer`; it's decorative, so it isn't a focusable button.
  - **Reduce Motion:** under `prefers-reduced-motion: reduce`, render `<BrandLogo>` instead, with no video and no timers.
  - **Cleanup:** clear the timer and disconnect the observer on unmount.

**Interfaces:**
- Consumes: `/brand/godoggydate-logo.webp` from Task 1.
- Produces: `BrandLogo({ height }: { height: number }): JSX.Element`. It renders a `next/image` of the logo with `alt="GoDoggyDate"`, inside a rounded (`rounded-lg`), `overflow-hidden` box with width `height × 3.9`. The image uses `object-cover object-center`, so the blue margin above and below the art falls outside the box and the file stays uncropped. Header use is `height={40}`.

### Change after build: cut-out logo (owner approved, 2026-11-25)

The website now uses versions of the logo and animation with the flat sky-blue background removed. The opaque `/brand/godoggydate-logo.webp` and `/brand/godoggydate-logo-animated.mp4` are gone; the originals stay in `docs/superpowers/specs/assets/`.

- `web/public/brand/godoggydate-logo-cutout.webp` (1774×887, alpha): `ffmpeg -i <logo-final.webp> -vf "colorkey=0x75C4F9:0.18:0.08" -pix_fmt rgba cut.png`, then `cwebp -q 90 -alpha_q 100 cut.png -o <out>`.
- `web/public/brand/godoggydate-logo-animated-cutout.webm` (VP9 with alpha, for Chrome, Firefox and Edge): `ffmpeg -i <animated.gif> -vf "scale=358:268:flags=lanczos,colorkey=0x70C5FA:0.2:0.08,format=yuva420p" -c:v libvpx-vp9 -b:v 0 -crf 30 -auto-alt-ref 0 <out>`.
- `web/public/brand/godoggydate-logo-animated-cutout.mov` (HEVC with alpha, for Safari and iOS): `ffmpeg -c:v libvpx-vp9 -i <webm> -c:v hevc_videotoolbox -alpha_quality 0.75 -allow_sw 1 -tag:v hvc1 -movflags +faststart <out>`.
- `AnimatedLogo` lists the `.mov` first (`type='video/mp4; codecs="hvc1"'`), then the `.webm`, so each browser picks the one whose transparency it can show. `BrandLogo` and the poster use the cut-out webp.
- Tests: `cut-out logo has transparency and the art size`; `every brand file the site ships is used, and every used one exists`.
