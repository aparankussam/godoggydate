# Build 40: Dogtype card, Playroom, honest types, website parity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (inline, as the owner chose). Steps use checkbox syntax.

**Goal:** Build everything in the spec's addenda A1-A4 plus the owner's "before build 40" list, on iPhone and website together, and fix the website's small profile photo.

**Architecture:** New synced progress fields (`dogtypeRevealed`, `dogtypeDogs`) in `shared/progress.ts`; new shared modules (`dogtypeQuiz`, `profileHints`); iPhone and web UIs consume them. Website mirrors the app's structure: Profile = big cover + sections; Playroom is its own nav item.

**Tech Stack:** Expo/React Native, Next.js, Firestore, `node --test shared/*.test.ts`.

**Spec:** `docs/superpowers/specs/2026-11-23-profile-and-dogtype-discovery-design.md` (sections A1-A4 and B1-B9). Mockups: https://claude.ai/artifact/2vCcBVpDfScKDduEzixVyA

## Global Constraints

- No screen/page/preview may name, picture or hint at a type the owner hasn't met. The Zoomie Menace sample on the welcome screen and homepage is the one exception.
- Compatibility is a vibe tier, never a number. The old fit score on the match screen stays and is labelled separately from the Dogtype vibe.
- One pink action per screen/section. Tokens in `mobile/constants/theme.ts`; web uses Tailwind tokens (`bg-paper`, `border-brown`, `font-display`).
- Before any push touching `shared/` or `web/`: `npm run build` in `web/`, typecheck mobile and web, `node --test shared/*.test.ts`, and `npm run lint` in both.
- Import Firebase on web from `web/shared/utils/firebase` (a path of `../shared/utils/firebase` from `web/components`), never from the repo-root `shared/`.
- Do not deploy Cloud Functions, push, or run a TestFlight build without the owner's go-ahead for that step.
- Commit trailer: `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.

## Review Focus

1. Sealed card must not leak: before the first reveal, neither the card, the summary chip, nor the own-type tile may show the type name.
2. A matched dog's later profile edit must NOT discover a new type (snapshot at first sight), and must not change an already-discovered entry.
3. Quiz: every one of the 16 codes reachable, answers 5-8 can change the result, and quiz code equals `computeDogtype` of the profile built from `profileHintsForCode(code)`.
4. Match modal on a small phone: both buttons visible without scrolling; blocked READ FIRST still gates "Say hi".
5. Website: each page still works signed out (no crash) and the big cover never overflows at 390px.
